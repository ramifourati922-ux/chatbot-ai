1. DÉMARRAGE (dans cet ordre)
-------------------------------------------------------------------------------
[ ] 1.1  Vérifier que le PostgreSQL NATIF de Windows est arrêté (il vole
         le port 5432 à celui de Docker ; problème rencontré le 27/09) :
             Get-Service postgresql-x64-18
         → doit afficher « Stopped ». Sinon, dans un PowerShell ouvert en
         administrateur :  Stop-Service postgresql-x64-18

[ ] 1.2  Lancer Docker Desktop (menu Démarrer), attendre que l'icône de
         la baleine soit stable (~1 min), puis :
             docker compose up -d
         (JAMAIS « docker compose down -v » : -v efface les données.)

[ ] 1.3  Lancer l'API dans un terminal dédié (le laisser ouvert) :
             $env:HF_HUB_OFFLINE="1"
             .\venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
         HF_HUB_OFFLINE=1 : les modèles sont déjà en cache, on évite tout
         téléchargement (le réseau Hugging Face a déjà bloqué, cf.
         CHANGELOG). Attendre ces deux lignes (~10-20 s) :
             ✅ RAG préchargé (mode=advanced) en ...s
             INFO:     Application startup complete.
         Normal : deux avertissements « Embeddings illisibles dans
         ChromaDB » s'affichent au démarrage (anomalie n°7, contournée).

2. VÉRIFICATIONS (dans un second terminal)
-------------------------------------------------------------------------------
[ ] 2.1  Les 4 conteneurs tournent :
             docker compose ps
         → chatbot_postgres, chatbot_redis, chatbot_chroma, chatbot_adminer
           tous « Up »
[ ] 2.2  Chaque service répond :
             docker exec chatbot_postgres pg_isready -U chatbot_user -d chatbot_db
               → « accepting connections »
             docker exec chatbot_redis redis-cli ping
               → « PONG »
             curl.exe -s localhost:8001/api/v2/heartbeat
               → {"nanosecond heartbeat": ...}

               → {"status":"healthy","version":"1.0.0"}

             .\venv\Scripts\python.exe -c "from app.services.rag import vector_store as v; print(v.count())"
               → 11109
[ ] 2.4  Internet et Groq répondent : ouvrir un onglet
             http://127.0.0.1:8000/chat-demo

             Quel est le délai pour retourner un produit ?
         → réponse « 7 jours calendaires » en ~1-2 s. Si ça échoue, voir
         le plan de secours (section 4). Puis FERMER cet onglet.

4. PLAN DE SECOURS
-------------------------------------------------------------------------------
Symptôme → action

• Badge rouge / « Déconnecté » dans l'interface
    → l'API est tombée : regarder le terminal uvicorn, le relancer
      (étape 1.3), recharger la page (nouvelle session : reprendre le
      scénario depuis l'étape 1).

• Les étapes 1, 4, 6 et 8 marchent mais 2, 3, 5 et 7 échouent ou
  coupent la connexion
    → Groq injoignable (Internet ou quota). Basculer sur le partage de
      connexion du téléphone et réessayer. Si ça ne revient pas :
      terminer en live avec les étapes qui marchent SANS Internet
      (1 salutation, 4 merci, 6 escalade, 8 confiance faible : elles
      n'appellent pas le LLM), puis montrer la vidéo de la veille pour
      les étapes RAG.
      À dire : « la génération passe par l'API Groq ; la recherche et
      les garde-fous, eux, tournent en local, comme vous venez de le
      voir. »

• Réponse très lente (> 10 s) ou message d'erreur Groq 429
    → quota Groq atteint (ne pas avoir lancé de tests le jour même !).
      Le bot bascule seul sur le modèle de secours (gpt-oss-20b) ; sinon,
      vidéo.

• « Error: connect ECONNREFUSED » / l'API ne démarre pas
    → docker compose ps : un conteneur est arrêté ? docker compose up -d.
      Port 5432 : refaire l'étape 1.1.

• Une réponse différente de celle attendue (le LLM reformule)
    → normal si le contenu est le même (formulation variable). Si le
      contenu est faux : ne pas insister, passer à l'étape suivante.

• Tout est perdu (PC, Docker...)
    → vidéo de la répétition (clé USB) + TRANSCRIPTION_DEMO_VERIFIEE.txt
      + captures du rapport (docs/screenshots : figure22 escalade,
      figure24 garde-fou hors sujet) + résultats RAGas
      (docs/evaluation/ragas_results.md).
      Attention : les captures chat_demo_*.png et figure27-29 datent
      d'AVANT les correctifs du 27/09 (« Bonjour » y affiche
      « intent: general · confiance 0.00 ») : ne pas les présenter comme
      le comportement actuel.
